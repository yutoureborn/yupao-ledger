# 1. 项目定义

## 1.1 产品定位

芋炮小账本是一款面向双人家庭使用的在线收支记录工具。

产品重点不是堆叠复杂财务功能，而是让两个人可以在手机、平板和电脑上，快速完成记账、查账、看预算和查看收支趋势。

项目必须是可实际运行的全栈应用，不是纯静态页面、视觉演示稿或只能浏览的 HTML 原型。

系统需要具备：

- 云端数据读写
- 双人身份识别
- 多设备同步
- 动态数据刷新
- 表单交互
- 页面状态管理
- 图表动画
- 角色动画
- 操作反馈
- 错误处理
- 备份与恢复能力

---

## 1.2 产品目标

### 核心目标

1. 记账步骤少，手机上单手也能完成。
2. 两名用户能够共享家庭账本。
3. 数据通过云端保存，不依赖某一台设备。
4. 页面拥有自然、克制的动态交互。
5. 风格可爱，但不幼稚、不花哨。
6. 长期运行成本尽量保持在免费额度内。
7. 项目结构清晰，便于后续继续由 Codex 或其他开发工具维护。

### 非目标

第一阶段不开发：

- 原生 iOS 或 Android App
- 银行账户自动同步
- 投资理财行情
- 多家庭、多组织权限系统
- AI 强依赖功能
- 商业 OCR 服务
- 社区、排行榜或公开分享
- 复杂财务会计模块

# 3. 动态应用要求

## 3.1 禁止做成纯静态页面

项目不能只实现：

- 固定数字卡片
- 写死的图表数据
- 不能提交的表单
- 只能点击跳转的展示页面
- 仅用于查看视觉效果的 Demo
- 用本地 JSON 模拟最终数据

开发过程中允许使用 mock 数据辅助 UI 开发，但最终交付必须连接真实 Worker API 和 D1 数据库。

---

## 3.2 动态能力范围

项目至少需要实现以下动态能力：

### 数据动态

- 新增账目后首页数据立即更新
- 修改或删除账目后图表同步变化
- 账户余额根据交易动态计算
- 预算进度根据本月账目动态计算
- 筛选条件变化后列表即时刷新
- 切换月份后重新加载统计数据
- 两台设备重新进入页面后能获取最新数据

### 交互动态

- 页面转场
- 卡片进入动画
- 按钮按压反馈
- 表单字段切换动画
- 保存成功反馈
- 删除确认交互
- 下拉刷新或手动刷新反馈
- 加载骨架屏
- 空状态角色动画
- 图表数据切换动画

### 状态动态

页面必须覆盖：

- 初始加载
- 加载完成
- 空数据
- 提交中
- 提交成功
- 提交失败
- 网络断开
- 权限失效
- 数据冲突
- 删除恢复

# 6. 动画与微交互系统

## 6.1 动画原则

动态交互服务于信息理解和操作反馈，不作为纯装饰。

每个动画必须至少满足一个目的：

- 表示操作已发生
- 表示数据正在变化
- 帮助理解页面层级
- 减少等待焦虑
- 增强角色陪伴感

禁止没有目的的大面积循环动画。

---

## 6.2 动画层级

### Level 1：基础反馈

适用于所有操作：

- 按钮按下缩放
- Hover 轻微上浮
- 输入框聚焦
- 切换标签滑块
- Toast 淡入淡出

建议时长：

- 120–220ms

### Level 2：页面与模块转场

适用于：

- 页面切换
- Drawer 展开
- Modal 打开
- 图表卡片进入
- 筛选面板展开

建议时长：

- 180–320ms

### Level 3：角色与成功反馈

适用于：

- 记账成功
- 完成预算目标
- 空状态
- 首次进入
- 月度总结

建议时长：

- 400–900ms
- 循环待机动画必须低频、低幅度

---

## 6.3 主要动画清单

### 登录页

- 芋头角色轻微上下浮动
- 炮台偶尔弹出一枚金币
- 登录卡片淡入
- 登录成功后角色做一次点头

### 首页

- 核心金额从旧值平滑过渡到新值
- 概览卡片按顺序进入
- 最近账目列表轻微错峰出现
- 预算进度条从 0 动画到真实进度
- 收支小趋势图绘制动画

### 记一笔

- 支出/收入/转账切换时背景色柔和过渡
- 数字金额输入产生轻微缩放反馈
- 分类图标点击后有弹性反馈
- 保存按钮进入 loading 状态
- 成功后炮台发射一枚金币或小收据
- 成功提示出现后自动收起

### 明细页

- 筛选器展开/收起
- 日期分组内容淡入
- 删除后记录缩小并淡出
- 撤销后记录回到原位置
- 编辑保存后对应行短暂高亮

### 统计页

- 柱状图从底部生长
- 折线图从左到右绘制
- 环形图逐步填充
- 切换月份时图表平滑变形
- 点击分类后列表内容联动更新

### 预算页

- 预算进度条动态更新
- 接近上限时炮台角色轻微提醒
- 超出预算时不使用爆炸效果
- 使用柔和的晃动和提示卡片

### 空状态

- 芋头抱着空账本
- 炮台偶尔探头
- 动画不超过 3–5 秒一轮
- 不抢占主要操作按钮注意力

---

## 6.4 动画性能要求

- 动画优先使用 `transform` 和 `opacity`
- 避免频繁动画宽高、顶部和左侧位置
- 禁止在低端手机上持续运行大量粒子
- 图表切换过程中不能阻塞交互
- 动画资源按页面懒加载
- 大型动画资源必须压缩
- 首屏不加载非必要角色动画
- 动画不得显著增加首页加载时间

---

## 6.5 减少动态模式

必须支持系统的 `prefers-reduced-motion` 设置。

开启减少动态后：

- 关闭角色循环浮动
- 页面转场改为快速淡入
- 图表不使用复杂绘制动画
- 数字直接更新
- 保留必要状态反馈

# 9. 动态数据交互策略

## 9.1 请求状态

统一请求状态：

```text
idle
loading
success
error
refreshing
```

所有页面不得只显示空白等待。

加载时使用：

- 骨架屏
- 局部 loading
- 图表占位
- 角色轻量等待动画

---

## 9.2 乐观更新

适合使用乐观更新的操作：

- 新增交易
- 修改备注
- 修改分类
- 调整排序
- 删除后撤销

规则：

- UI 先响应
- API 失败时回滚
- 显示明确错误
- 不能悄悄丢失数据

不建议乐观更新：

- 大额批量导入
- 删除账户
- 修改期初余额
- 数据恢复

---

## 9.3 缓存与刷新

- 首页概览短时间缓存
- 统计数据按月份缓存
- 新增、修改、删除交易后主动失效相关缓存
- 切回页面时检查数据新鲜度
- 提供手动刷新入口
- 不在浏览器长期缓存完整账本

---

## 9.4 多设备一致性

MVP 不要求 WebSocket 实时推送。

采用：

- 页面进入时获取最新数据

# 15. 安全要求

## 15.1 身份与权限

- Cloudflare Access 指定邮箱白名单
- Worker 验证 Access JWT
- 邮箱映射内部用户
- API 自动注入 household_id
- 所有资源查询必须包含 household_id 条件
- 前端不得决定用户身份

## 15.2 数据安全

- SQL 参数化
- 输入长度限制
- 金额范围校验
- 日期格式校验
- 审计关键写操作
- 删除采用软删除
- 导出接口限制频率

## 15.3 浏览器安全

- HTTPS
- CSP
- `X-Content-Type-Options`
- `Referrer-Policy`
- `frame-ancestors`
- API 响应使用合适的缓存策略
- 财务数据接口默认 `no-store`

## 15.4 日志

不得记录：

- 完整账目备注
- Access Token
- Cookie
- 导出文件内容
- 完整个人邮箱日志

可记录：

- request_id
- 接口路径
- 状态码
- 耗时
- 匿名用户标识
- 错误类型
